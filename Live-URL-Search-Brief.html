Why this exists

No middleman to go down

Earlier versions of this feature searched the open web through a third-party search service to find relevant pages before answering. That worked, but it added a dependency the team doesn't control: the search provider could rate-limit or block requests, and when it did, the assistant simply stopped finding anything from the web.

This version removes that dependency entirely. It never asks anyone else's search engine anything. It goes straight to the websites already on your tracked list, reads them itself, and answers only from what it actually finds there. If a tracked site is up, the feature works — full stop.

How it works

Six steps, one question

  1. Tracked URLs. The assistant reads your list of tracked website URLs from SharePoint — the same list your team maintains today.
  2. Crawl. It downloads each tracked page, then reads the links on that page and follows the ones pointing to more content on the same website (product pages, articles, categories). Links to social media, login pages, carts, and search results are filtered out automatically.
  3. Rank. Every page it found — the tracked page and its sub-pages — gets scored against the question by comparing words in the title. This is plain text comparison, not an AI call, so it costs nothing and takes milliseconds.
  4. Fetch content. Only the two highest-scoring pages get their full text downloaded and cleaned up (navigation menus, footers, and scripts stripped out).
  5. Generate. That text is handed to GPT-4o with strict instructions: answer only from what's here, and say plainly which of these two pages the answer actually came from.
  6. Answer. The response includes the real page the answer was drawn from — not just whichever page happened to be searched — plus up to three follow-up questions the assistant has already confirmed it can answer from the same content.
Known limitation

The crawl currently goes one level deep from each tracked URL. A question that needs a very specific sub-page — one that's itself linked from a sub-page, two clicks from the tracked URL — may not be found. In practice this mostly affects narrow, multi-part questions (e.g. a specific product spec buried in a listing page's own sub-links). A second crawl level is a straightforward addition if this shows up often enough to matter.

What it's built on

The stack

Azure Functions

Runs the whole flow on demand, per question — Python, Consumption plan, no server to manage or pay for while idle.

requests + BeautifulSoup

Fetches each page over plain HTTP and reads its title, links, and body text — the same libraries used to build the ticket/document sync.

RapidFuzz

Scores page titles against the question locally, in-process. No network call, no API cost.

Azure OpenAI — GPT-4o

Writes the final answer from the fetched page text and reports exactly which source it used. The only paid AI call in this entire flow.

SharePoint (via Microsoft Graph)

Source of truth for which URLs are tracked — the same list your team already edits.

Notably absent: Azure AI Search and text embeddings. Those power the ticket and document search paths, but this feature doesn't touch them — ranking is done by title-matching, not vector search, which is exactly why the only per-question cost is the one GPT-4o call below.

Worked example

A typical question fetches two pages (~6,000 characters each) plus the question itself and a short answer format instruction — call it roughly 4,500 input tokens and 400 output tokens:

Input — 4,500 tokens × $2.50 / 1M$0.0113
Output — 400 tokens × $10.00 / 1M$0.0040
Cost per question answered from a live website ≈ $0.015 AUD*

*Converted at indicative USD/AUD rates; Azure bills in the currency of your subscription. At 5,000 questions a month through this path, that's roughly $75 — a fraction of a single support ticket's handling cost.

See it working

A real question, answered live

Captured directly from the test environment — including a follow-up, to show the assistant carrying context between turns:

tell me about lenovo laptops
No confident match found in the tracked pages for this exact wording — the assistant reports "not found" rather than guessing.
is it good for gaming?
Yes, Lenovo laptops can be good for gaming, especially models like the Lenovo Legion Pro 7 and Lenovo LOQ series.

— Legion Pro 7: Intel Core i9-14900HX, NVIDIA GeForce RTX 4080 16GB, 16GB DDR5 RAM, 16″ WQXGA 240Hz display — built for high-performance gaming.
— LOQ series: AMD Ryzen processors, NVIDIA GeForce RTX GPUs, 144Hz displays — a mid-range gaming option.
Source: Gaming Laptops — intaglaptops.com

The second question says "it" — nothing about laptops. The assistant resolved that from the first turn, combined it with "gaming," and pulled real, specific model names and specs straight out of the fetched page text. Nothing here was invented — everything traces back to the cited source link.

Where this fits

One of three ways the assistant answers

This is the last of three sources the assistant checks, in order: closed support tickets first (a real resolution beats generic documentation), then your SharePoint knowledge library, and finally — only if neither answers the question — a live look at your tracked websites, exactly as described above. The old search-engine-based version of this feature (SearXNG) remains in the codebase, disabled, as a fallback design if it's ever needed again.
